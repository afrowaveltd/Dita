# 自动翻译处变动摘要

## 概览

本文件总结了对Dita自动翻译服务的所有修改,包括架构重构,新功能,可观察性改进和本地化增强等.

## 结构变化

### 重构后端翻译服务

该单体被分解为由轻量级管弦乐团协调的4个专业服务:

- ** Backend 翻译服务** — 管道管弦乐器(服务器验证,舞台授权,错误处理)
- ** Countries Translation Service** — 国名同步(英语-目标语言)
- ** 本地化 翻译服务**——JSON词典同步(加/去除密钥)
- ** 文件翻译服务** — 有块级跟踪的标记下文件翻译
- ** SignalRPublisher**——通过SignalR实时进度报告
- ** 翻译服务**——保留占位符的阶段级重试

### 福利

- ** 消除关切**: 每个服务处理一个单一翻译域
- ** 维持能力**: 更小的班级更容易理解和测试
- ** 延期**: 通过接口实施可增加新的翻译目标
- ** 可靠性**:独立服务提供更好的断层隔离

## 新特性

### 现场翻译监视器

** 地点**:

为翻译管道提供实时能见度的新管理员页面:

- 显示所有信号事件发生时
- 颜色编码消息类型(蓝色=启动,绿色=完成,红色=错误)
- 自动重联连接状态横幅
- 信件计数器并导出到 JSON

### 已命名的占位符

本地化系统现在支持命名的占位符 () 改善不同语言的语法:

```csharp
// Usage in code
var message = Localizer["WelcomeMessage", new Dictionary<string, string>
{
    ["userName"] = "John",
    ["count"] = "5"
}];
// Result: "Hello John, you have 5 new messages"
```

特征 :
- 运行时提供的或存储在
- 翻译期间自动蒙面/修复以防止腐败
- 向后兼容现有位置占位符

### 递增翻译

Markdown 文件被递增翻译 :

- ** 节省费用**: 每个目标语言在翻译后立即被保存,降低内存压力
- ** 锁级跟踪**:每个区块的轨道翻译状况
- ** 选择性重试**: 下一次运行时只重新翻译出已失败的块
- ** 数据持久性**: 翻译状态在应用程序重新启动后幸存

### 增强重试逻辑

三个层次的复原力:

1. ** HTTP 重试** (Libre Translate Service): 有5次尝试带有指数后退(1s-5s)
2. ** 重复试验**(翻译服务):另外3次尝试,30起延误
3. ** Block 重试 ** (Documents Transformation Service): 在下次运行时重试了 Markdown 块失败

### 信号报告

所有管道业务的实时进度报告:

- 每个阶段都发表活动
- 作为活动发表的各语文进展
- 出错事件包括详细的上下文(来源,出错代码,消息)
- 序列号保证在每次运行中订购

所有变化都是添加剂:

- 现有本地化代码()不变
- 定位格式()工作不变
- 现有的 JSON 字典格式不变
- 现有的Markdown结构不变
- 信号R 消息使用相同的格式

## 迁移路径

不需要移徙。 重构为内:

1. 旧的被保存下来作为参考,然后被替换
2. 更新了DI注册,以使用新的接口
3. 所有现有消费者均无变化

## 业绩改进

- ** 内存使用减少**: 立即保存每个语言的文件, 而不是保存全部内存
- ** 快速递增运行**: 只有已更改/ 失败的 Markdown 块被重新翻译
- ** 提高能见度**: 实时进展有助于诊断缓慢阶段
