# 实时翻译

此文档作为自动翻译管道的活性测试输入而存在. 此文件的任何更改都会触发在下一次预定运行中重新翻译所有目标语言文件.

## 结构概览

翻译管道已改组为模块结构,由轻量级管弦乐员协调四个专业分服务:

- ** Backend Transference Service** — Orchestrates the whole production, handle server 验证,并派代表到分公司工作.
- ** 国家翻译服务**——同步将国名从每个语种的词典变为每个语种的词典.
- ** 本地化翻译服务**——检测在默认的JSON词典中添加/删除了密钥并翻译成目标语言.
- ** 文件翻译服务**——将Markdown文件文件按区块跟踪和元数据翻译.

每个子服务独立运行,并通过信号R实时报告进度.

## 服务的作用

该服务运行在时间表上,并执行一个五阶段的管道:服务器验证,国家同步,JSON词典同步,Markdown文件翻译,以及持续结果. 每个阶段通过信号发布结构化实时进度事件 R使得连接的客户端能够随着工作进展而来.

## 管道阶段

### 第一阶段——检查员

在任何翻译工作开始之前,服务核实所有先决条件都得到满足:

- 配置部分必须在场且有效.
- LibreTranslate服务器必须在可接受的空闲时间内响应.
- 获取翻译服务器上可用的语言列表 .
- 所配置的默认语言必须在列表中显示 .
- 缺少任何支持语言的地语JSON文件会自动创建.

如果任何检查失败, 管道会立即停止, 并发出消息 .

### 第2阶段——翻译国

从只读目录()到本地化的JSON词典,国家名称保持同步.

- 如果应用程序默认语言为英语,则每个国家名称被存储为无翻译.
- 如果默认语言是任何其他语言,则英语国家名会先被翻译成该语言,结果成为默认词典中的条目.
- 默认词典被更新后,每个目标语言词典中每一个缺失的国家条目都会被翻译并被保存**每个语言立即**.
- 已翻译的条目未经修改而保留.
- 如果翻译失败,服务在移动到下一种语言前最多重复了3次,延迟了30秒.

### 第3阶段——翻译Json档案

该服务将当前默认本地化词典与上一个运行存储的快照进行比较:

- ** 已添加的密钥** —— 在当前默认中存在但快照中缺失的条目—— 被翻译成尚未有该密钥手动条目的每一种目标语言.
- ** 从每个目标语言词典中删除已删除的密钥**——快照中存在但当前默认缺漏的条目.
- 手工翻译总是优先。 如果目标字典已经包含一个密钥的值,则无论来源怎么说,该条目都保持不变.
- ** 每个目标语言词典在翻译完成后立即被保存**,而不是等待所有语言完成.
- 如果某一语言的翻译失败,服务会自动重复。 只有持久错误(如不支持的语言)导致该语言被跳过.
- 运行后,当前默认字典被保存为下个比较的新快照.

所有词典总是用字母排序的密钥和缩进的JSON来存储,用于人类的可读性.

### 第4阶段——翻譯馬克倒地檔案

该服务将所配置的文档根( 默认: ) , 并循环处理每个源文件 :

1. 源文件内容被读取并计算出SHA-256散列.
2. 源音轨旁边的文件,每个语言,每个块的翻译状态,允许**incental再翻译**只失败的块.
3. 从上行所存储的散列(在源文件旁边的文件中被隐藏,或者在一个临时倒置位置)被比作当前散列.
4. 对于每种目标语言,也检查相应的文件的结构完整性.
5. 任何缺少的目标文件,有过时的散列,失败的结构验证,或包含未翻译的块会被排队重新翻译.
6. ** 每一种目标语言都独立地翻译和保存**——如果捷克成功但法语失败,捷克文件仍然被写入磁盘.
7. 成功翻译的文件在被写入磁盘之前会被验证为结构等同源(等标题计数,列表项目,代码块,块名,链接,粗体/斜体标记,和HTML标记).
8. 如果一个源的所有目标文件都成功,新的散列存储在源旁边. 如果在源旁边写入失败(例如只读部署),散列会倒回临时目录.
9. 如果任何目标翻译失败验证, 元数据会将这些块标记为未翻译的块, 因此它们会在下一次运行中重新测试 .

### 第5阶段——储存结果

合并后编集出版. 它包括:

- UTC运行起跑和完成时间戳.
- 已保存的 locale JSON 文件数, 保存了 Markdown 文件, 保存了散列文件, 以及倒回散列文件 .
- 在运行中收集到任何存储错误 .
- 每种语言的翻译统计(翻译计数,跳过计数,出错计数).

## 翻译重试逻辑

管道实施两个层次的复原力:

### 阶段级重试( 翻译服务)

- 如果在Libre Translate的内部重试后翻译请求失败,则履行最多可增加3个舞台级重试,延迟30秒.
- 占位符遮盖 : 文本中被命名的占位符 () 在翻译前被暂时替换为安全符 () 后被恢复,确保目标语言的语法正确.

### 语言验证

- 在翻译为目标语言之前,服务验证语言得到翻译服务器的支持.
- 不支持的语言会被以警告跳过,防止重复失败的尝试.

### 标记下块级重试

- 分块翻译(标题、段落、清单项目).
- 如果单个块翻译失败,则在元数据文件中标为未翻译,并在下个管道运行时重新测试.
- 每个源 Markdown 文件旁边的文件的每个语言,每个块状态的服务跟踪.

## 错误代码

报告错误时使用一个按范围分类的统一语句:

范围
|-------|----------|
1,000 - 1999 (单位:千美元)
2000 -- 2999年
3000-3999 (中文(简体) )
4000-4999 (中文(简体) )
5000-5999 (中文(简体) )

报告中的每个出错都带有源标识符(语言代码,文件路径,或艺名),出错代码,以及可被人读取的信息.

## 现场翻译 Dashboard

服务器项目包括一个管理页面,该页面可实时连接到SignalR中枢并显示所有管道事件.

- 显示连接状态、 信件数和所有事件的活更新表.
- 彩色编码行:为舞台起步用蓝色,为完成用绿色,为出错用红色.
- 支持清除种子并将所有消息导出到 JSON .
- 如果连接下降,则自动重联与指数回放.

## 设计原则

- ** 模式**:为了维持和检验起见,每个翻译问题都是孤立的.
- ** 递增持久性**: 词典和Markdown文件在翻译后立即被每个语言所保存,降低了内存压力并提供了更早的反馈.
- ** 响应**:多重试水平(HTTP,相位,块位)确保瞬间故障不会阻断管道.
- ** 国家追踪**: 每个文件的元数据()和散列文件可以使随后运行的精确增量工作得以进行.
- ** 实时可见度**: 每个重大行动都通过信号R报告,用于监测和调试.
- **Manual translations always have priority over automatic additions.**
