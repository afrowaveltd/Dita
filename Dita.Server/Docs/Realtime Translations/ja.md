# リアルタイム翻訳

このドキュメントは自動翻訳パイプラインのライブテスト入力として存在します。 このファイルの変更は、次のスケジュールされた実行上のすべてのターゲット言語ファイルの再変換をトリガーします.

## 建築概要

トランスレーションパイプラインは、軽量のオーケストレーターによって調整された4つの専門サブサービスを備えたモジュラーアーキテクチャに再構成されています

- **BackendTranslationService** — パイプライン全体をオーケストし、サーバーの検証を処理し、サブサービスに作業を委任します.
- **CountriesTranslationService** — 各国名を言語ごとに同期させる.
- **LocalizationTranslationService** — 既定の JSON 辞書で追加/削除されたキーを検出し、それらをターゲット言語に変換します.
- **DocumentsTranslationService** — マークダウンのドキュメントファイルをパーブロックトラッキングとメタデータで翻訳します.

各サブサービスが独立して運用し、リアルタイムでSignalRを介して進捗を報告します.

## サービスが何であるか

サービスはスケジュール上で実行され、5段階のパイプラインを実行します:サーバーの検証、国同期、JSON辞書の同期、Markdownファイル翻訳、および結果の持続。 各ステージは、Connectedクライアントが作業を進めることができるように、SignalR 上で構造化されたリアルタイム進行イベントを生成します.

## パイプラインステージ

### ステージ1 — CheckServers

翻訳作業が始まる前に、サービスはすべての前提条件が満たされていることを確認します

- 設定セクションは、現在および有効である必要があります.
- LibreTranslateサーバーは、許容レイテンシ内で応答しなければなりません.
- 翻訳サーバーで利用可能な言語のリストが取得されます.
- 設定されたデフォルト言語は、そのリストに存在する必要があります.
- サポートされている言語の locale JSON ファイルを自動的に作成します.

チェックが失敗すると、パイプラインはすぐに停止し、メッセージが発信されます.

### ステージ2 — 翻訳数

国名は、読み専用カタログ()からローカリゼーションJSON辞書に同期して保存されます.

- アプリケーションのデフォルト言語が英語の場合、各国名は翻訳なしで保存されます.
- デフォルト言語が他の言語であれば、英語の国名は最初にその言語に翻訳され、結果はデフォルトの辞書のエントリになります.
- After the default dictionary is updated, each missing country entry in every target language dictionary is translated and saved **immediately per language**.
- すでに翻訳されたエントリは変更なしで保存されます.
- 翻訳が失敗した場合は、次の言語に移行する前に30秒の遅延で最大3回のサービスが回復します.

### ステージ3 — TranslateJsonFiles

サービスは、以前の実行から保存されたスナップショットで現在のデフォルトのローカリゼーション辞書を比較します

- **キーを追加** — 現在のデフォルトに存在するエントリがスナップショットから存在しない — は、既にそのキーの手動入力を持っていないすべてのターゲット言語に翻訳されます.
- **Removed キー** — スナップショットに存在するエントリが、現在のデフォルトから存在しない — は、すべてのターゲット言語の辞書から削除されます.
- マニュアル翻訳は常に優先します。 ターゲット辞書がキーに値が既に含まれている場合、そのエントリはソースが言うものに関係なく変更されません.
- **Each target language dictionary is saved immediately after its translations complete**, rather than waiting for all languages to finish.
- 特定の言語で翻訳が失敗した場合は、自動的にサービスが削除されます。 永続的なエラーのみ(サポートされていない言語など)は、その言語がスキップされる原因となります.
- 実行後、現在のデフォルト辞書は、次の比較の新しいスナップショットとして保存されます.

すべての辞書は、常にアルファベット順に並べ替えられたキーで保存され、人間の読みやすさのためにJSONをインデントします.

### ステージ4 — TranslateMarkdownFiles

サービスは、設定されたドキュメントルート(デフォルト: )を歩き、すべてのソースファイルを再帰的に処理します

1. ソースファイルの内容は読み込まれ、SHA-256ハッシュは計算されます.
2. A `.translation-meta.json` file next to the source tracks per-language, per-block translation status, enabling **incremental re-translation** of only failed blocks.
3. 前の実行から格納されたハッシュ(ソースファイルの隣にあるファイル、または一時フォールバック位置)は、現在のハッシュと比較しています.
4. 各ターゲット言語では、対応するファイルは構造の整合性にもチェックされます.
5. 欠落している任意のターゲットファイル, 未処理のハッシュを持っています, 構造検証を失敗します, または未翻訳のブロックが再翻訳のためにキュートです.
6. **各ターゲット言語は翻訳され、独立して保存されます** — チェコが成功した場合、フランス語が失敗した場合、チェコファイルはディスクに書かれています.
7. 完全に翻訳されたファイルは、ソース(例の見出しカウント、リスト項目、コードブロック、ブロッククォート、リンク、太字/italicマーカー、およびHTMLタグ)で構造的なパリティのために検証されます.
8. ソースのすべてのターゲットファイルが成功すると、ソースの横に新しいハッシュが保存されます。 ソースの横に書くと失敗します(例えば、読み込み専用のデプロイメント)、ハッシュは一時ディレクトリに戻ります.
9. ターゲットの翻訳がバリデーションに失敗すると、メタデータはそれらのブロックを未翻訳にマークし、次の実行に取り戻されます.

### ステージ5 — ストリング結果

連結子会社化・公表 それは下記のものを含んでいます:

- UTCの起動と完了タイムスタンプを実行します.
- 保存された locale JSON ファイル数、保存された Markdown ファイル、保存されたハッシュファイル、およびフォールバックハッシュの書き込み.
- 実行中に収集したストレージエラー.
- 翻訳統計(翻訳数、省略数、エラー数).

## 翻訳リトリーロジック

パイプラインは、レジリエンスの2つのレベルを実装します

### ステージレベルのリトライ(TranslationRetryService)

- 翻訳リクエストがLibreTranslateの内部のリトリートの後に失敗した場合、30秒の遅延で最大3個の追加のステージレベルのリトリートを実行します.
- プレースホルダーのマスキング: テキストのプレースホルダー()は、翻訳と復元前の安全なトークン()に一時的に交換され、ターゲット言語の正しい文法を保証します.

### 言語検証

- 対象言語へ翻訳する前に、翻訳サーバーで言語を認証します.
- サポートされていない言語は警告でスキップされ、繰り返し失敗した試みを防ぎます.

### マークダウンブロックレベルの再試行

- マークダウン翻訳はブロック・バイ・ブロック(ヘッディング、段落、リスト項目)を実行します.
- 個々のブロックが翻訳に失敗した場合は、メタデータファイルで非翻訳としてマークされ、次のパイプラインの実行時に取得されます.
- サービスは、各ソースのMarkdownファイルの隣にあるファイルの1つの言語、ブロックのステータスを追跡します.

## ライブ翻訳ダッシュボード

Server プロジェクトには、SignalR ハブに接続し、すべてのパイプラインイベントをリアルタイムに表示する管理者ページが含まれています.

- すべてのイベントの接続状況、メッセージカウント、およびライブアップテーブルを表示します.
- 色分けされた行:段階の開始のための青、完了のための緑、間違いのための赤.
- フィードをクリアし、JSON にすべてのメッセージをエクスポートするサポート.
- 接続が低下すると、自動で接続します.

## デザイン原則

- **Modularity**:各翻訳上の問題は、保守性と試験性のために独自のサービスで隔離されています.
- **全面的な主張**: 辞書とMarkdownファイルは、翻訳直後に保存され、メモリの圧力を減らし、以前のフィードバックを提供します.
- **弾性**:複数のリトライレベル(HTTP、ステージ、ブロック)により、過渡障害がパイプラインをブロックしないことを確認します.
- **State Tracking**: パーファイルメタデータ()とハッシュファイルにより、その後の実行時に正確な増分作業が可能になります.
- **リアルタイムの可視性**: 監視やデバッグのために、SignalR を介して重要な操作が報告されます.
- **マニュアル翻訳は、常に自動追加を優先しています。**
