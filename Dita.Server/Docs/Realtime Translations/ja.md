# リアルタイム翻訳

このドキュメントは自動翻訳パイプラインのライブテスト入力として存在します.

## サービスが何であるか

本サービスは、翻訳作業を開始する前に、翻訳サーバー、設定、および利用可能な言語をスケジュールして検証します.

バリデーション・ステップの後、読まれた国のカタログから国名を標準のローカリゼーションJSON辞書に同期させます。 アプリケーションのデフォルト言語が英語の場合、国のエントリはキー等しい値として保存されます。 デフォルト言語が異なる場合、英語の国名は最初にデフォルト言語に翻訳され、デフォルト辞書のキー等しい値として保存されます.

次に、このサービスは、以前の実行から保存されたスナップショットで現在のデフォルトのローカリゼーション辞書を比較します。 新しく追加されたエントリは、キーが既に存在していない場合にのみ、ターゲット言語に翻訳されます。そのため、マニュアルの翻訳は優先的に保ちます。 削除されたエントリは、すべてのターゲット辞書から削除され、セット全体が一貫した状態を維持します.

最後に、サービスがマークダウンツリーのドキュメントルートをスキャンします。 各トピックフォルダには、en.md などのデフォルト言語で名前付けされたソースファイルを含むことが期待されます。 ソースファイル、変更を検出し、不足しているか、または未処理のMarkdownファイルを変換し、ソースファイルの隣に現在のハッシュを保存します。 ソースファイルの隣にハッシュを書くことは不可能な場合、一時的なストレージに戻ります.

## サービスレポートの進捗状況

バックエンドは、メッセージのエンベロープを使用してローカリゼーションハブを介して一般的なSignalRメッセージを発信します。 メッセージの種類、現在のプロセス段階、UTCタイムスタンプ、テキストサマリー、オプションのステージ固有のペイロードを処理します.

現在のステージは:

- チェックサーバ
- 翻訳数
- 翻訳JsonFiles
- TranslateMarkdownファイル
- ストリング結果

代表的なメッセージフローは、ステージ開始、ステージ完了、パイプライン完了です。 ステージが失敗すると、メッセージはエラーとしてマークされ、統一されたエラーコードで構造化されたエラー情報が含まれています.

## デザイン原則

翻訳は、LibreTranslateサーバーの過負荷を回避するために順次処理されます.

ローカリゼーションJSON辞書は、常にアルファベット順にソートされたキーとフォーマットされたJSONで保存され、メンテナンスが容易になります.

以前のデフォルトの辞書スナップショットは永続的に保存されますので、アプリケーションの再起動は変更トラッキングを失いません.

**マニュアル翻訳は、常に自動追加を優先しています。**
