# Переводы в реальном времени

Этот документ существует в качестве живого тестового ввода для конвейера автоматического перевода.

## Что делает служба

Сервис работает по расписанию и проверяет сервер перевода, конфигурацию и доступные языки перед началом любой работы по переводу.

После этапа проверки он синхронизирует названия стран из каталога только для чтения в стандартные словари локализации JSON. Если язык по умолчанию приложения является английским, запись в стране хранится как ключ, равный значению. Если язык по умолчанию отличается, английское название страны сначала переводится на язык по умолчанию, и только затем хранится в качестве ключа, равного значению в словаре по умолчанию.

Далее сервис сравнивает текущий словарь локализации по умолчанию с сохраненным снимком из предыдущего запуска. Вновь добавленные записи переводятся на целевые языки только тогда, когда ключа еще нет, поэтому ручные переводы сохраняют приоритет. Удаленные записи удаляются из всех целевых словарей, чтобы поддерживать согласованность всего набора.

Наконец, сервис сканирует настроенные корни документации для деревьев Маркдауна. Каждая папка темы должна содержать исходный файл, названный в честь языка по умолчанию, например en.md. Сервис хэширует исходный файл, обнаруживает изменения, переводит отсутствующие или устаревшие целевые файлы Markdown и хранит текущий хеш рядом с исходным файлом. Если записать хеш рядом с исходным файлом невозможно, он возвращается на временное хранение.

## Как служба сообщает о прогрессе

Бэкэнд испускает общие сообщения SignalR через концентратор локализации, используя один конверт сообщений. Каждое сообщение несет тип сообщения, текущий этап процесса, временную метку UTC, текстовое резюме и дополнительную полезную нагрузку для конкретного этапа.

Текущими этапами являются:

- Проверка серверов
- Переводные страны
- Перевод JsonFiles
- Перевод материалов MarkdownFiles
- Хранение результатов

Типичный поток сообщений начинается, завершается этап и завершается трубопровод. Если этап не удается, сообщение помечается как ошибка и включает в себя структурированную информацию об ошибке с унифицированными кодами ошибок.

## Принципы проектирования

Переводы обрабатываются последовательно, чтобы избежать перегрузки сервера LibreTranslate.

Словари JSON всегда хранятся с алфавитно отсортированными ключами и форматированными JSON для облегчения обслуживания.

Предыдущий снимок по умолчанию хранится постоянно, поэтому перезапуск приложения не теряет отслеживания изменений.

**Ручные переводы всегда имеют приоритет перед автоматическими дополнениями**
