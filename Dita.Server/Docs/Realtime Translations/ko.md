# 실시간 번역

이 문서는 자동 번역 파이프라인의 실시간 테스트 입력으로 존재합니다.

## 어떤 서비스는

이 서비스는 일정에 실행하고 번역 서버, 구성 및 모든 번역 작업이 시작되기 전에 사용할 수있는 언어를 검증합니다.

유효성 검사 단계 후, 읽기 전용 국가 카탈로그에서 표준 로컬화 JSON 사전으로 국가 이름을 동기화합니다. 응용 프로그램 기본 언어가 영어 인 경우, 국가 항목은 키 동등한 값으로 저장됩니다. 기본 언어가 다를 경우, 영어 국가 이름은 기본 언어로 처음 번역되며, 기본 사전의 키 동일값으로 저장됩니다.

Next는 이전 실행에서 저장된 스냅 샷으로 현재 기본 로컬라이제이션을 비교합니다. 새로 추가 된 항목은 키가 이미 존재하지 않는 경우에만 대상 언어로 번역되어 있으므로 수동 번역은 우선 순위를 유지하십시오. 제거된 항목은 모든 대상 사전에서 삭제되어 전체 설정 상태를 유지할 수 있습니다.

마지막으로 Markdown 나무에 대한 문서 루트를 구성하는 서비스 스캔. 각 항목 폴더는 en.md와 같은 기본 언어 후 지정된 소스 파일을 포함 할 것으로 예상됩니다. 서비스 hashes 그 소스 파일, 변경을 감지, 누락 또는 outdated 대상 Markdown 파일을 번역, 그리고 소스 파일 옆에 현재 해시를 저장. 소스 파일 옆에 해시를 작성하면 임시 저장소로 돌아갑니다.

## 서비스 보고서 진행 방법

백엔드는 하나의 메시지 envelope를 사용하여 로컬라이제이션 허브를 통해 일반 SignalR 메시지를 방출합니다. 모든 메시지는 메시지 유형, 현재 프로세스 단계, UTC 타임스탬프, 텍스트 요약 및 옵션 단계 별 페이로드를 운반합니다.

현재 단계는:

- 체크 서버
- 번역Countries
- 번역JsonFiles
- 번역MarkdownFiles
- 연락처

일반적인 메시지 흐름은 단계 시작, 단계 완료, 및 파이프라인 완료. 단계가 실패한 경우, 메시지는 오류로 표시되며 지정된 오류 코드와 구조화된 오류 정보를 포함합니다.

## 디자인 원칙

번역은 LibreTranslate 서버에 과부하를 피하기 위해 순차적으로 처리됩니다.

로컬라이제이션 JSON 사전은 항상 알파벳으로 정렬된 키와 포맷된 JSON으로 저장됩니다.

이전 기본 사전 스냅 샷은 영구적으로 저장되므로 응용 프로그램의 재시작은 변경 추적을 잃지 않습니다.

**자동 번역은 항상 자동 추가를 통해 우선 순위가 있습니다. **
