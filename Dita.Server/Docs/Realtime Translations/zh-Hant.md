# 实时翻译

该文件作为自动翻译管道的活性测试输入而存在.

## 服务的作用

服务按时间表运行,并在任何翻译工作开始前验证翻译服务器,配置和可用语言.

在验证步骤后,它将只读国家目录中的国名同步到标准本地化JSON词典. 如果应用程序默认语言为英语,则将国家条目存储为密钥等值. 如果默认语言不同,英语国家名会先被翻译为默认语言,然后在默认词典中作为键值存储.

接下来,服务将当前默认本地化词典与上次运行中存储的快照进行比较. 新加入的条目仅在密钥不存在时才被翻译成目标语言,因此手工翻译保留了优先级. 从所有目标词典中删除已删除的条目,以保持整个集的一致性.

最后,服务扫描为Markdown树配置了文档根. 每个话题文件夹预计将包含一个以默认语言命名的源文件,例如en.md. 服务将源文件的散列,检测变化,翻译缺少或过时的目标Markdown文件,并将当前散列存储在源文件旁边. 如果无法在源文件旁边写入散列,则会回落到临时存储.

## 服务报告的进展情况

后端使用一个消息信封通过本地化中心发送一般信号R消息. 每条消息都包含一个消息类型,当前处理阶段,UTC时间戳,文本摘要,以及可选阶段特定有效载荷.

目前的阶段是:

- 检查服务器
- 翻译
- 翻译 Json 文件
- 翻译 Markdown 文件夹
- 储存结果

典型的信息流是开始阶段,完成阶段,并完成管道. 如果一个阶段失败,则信件被标记为出错并包括结构化的错误信息并带有统一的出错代码.

## 设计原则

翻译按顺序处理,以避免LibreTranslate服务器超载.

本地化JSON词典总是用字母排序的密钥和格式化的JSON来存储,以便于维护.

之前的默认字典快照被持续存储,这样应用程序的重启不会丢失更改跟踪.

** 手册翻译总是优先于自动添加。 **
