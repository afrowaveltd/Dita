# Переклади

Цей документ існує в якості джерела даних для автоматичного перекладу. Будь-яка зміна цього файлу викликає переперенесення всіх цільових мовних файлів на наступний запланований курс.

## Огляд архітектури

У модульній архітектурі з чотирма спеціалізованими субсервісами, що координують легкий оркестратор:

- **BackendTranslationService** — Оркестр всього трубопроводу, ручка перевірки сервера та делегатів роботи на субсервісах.
- **CuntriesTranslationService** — Синхронізація назв країн із замовних словників.
- **LocalizationTranslationService** — Detects додано/видалено ключі у словнику за замовчуванням JSON та переводить їх на цільові мови.
- **DocumentsTranslationService** — Перекладає файли документації з відстеженням та метаданих.

Кожен субсервіс працює самостійно і веде звіти через SignalR в режимі реального часу.

## Що таке сервіс

Послуга працює на графіку і виконує п'ятиступінчастий трубопровод: перевірка сервера, синхронізація країни, синхронізація словника JSON, переклад файлів Markdown і збереження результатів. Кожен етап випромінює структуровані події в режимі реального часу на Signal R так, що підключені клієнти можуть слідувати за процесом роботи.

## Етапи трубопровідної труби

### 1 етап — CheckServers

Перед тим як розпочати роботу перекладу, служба перевіряє, що всі передумови задоволені:

- У розділі конфігурації необхідно бути присутнім і дійсним.
- Сервер LibreTranslate повинен відповідати в межах прийнятної затримки.
- Список мов, доступних на сервері перекладу, є fetched.
- Настрочені мови за замовчуванням повинні бути присутніми в цьому списку.
- Випробування локальних файлів JSON для будь-якої підтримуючої мови створюються автоматично.

Якщо будь-яка перевірка не вдається, трубопровід негайно припиняється і повідомлення вдається.

### 2 етап — перекладКурнітури

Назва країни зберігаються в синхронізації з каталогу прочитання () у локалізацію словників JSON.

- Якщо мова за замовчуванням програми англійською мовою, кожна назва країни зберігається без перекладу.
- Якщо мова за замовчуванням є іншою мовою, ім'я англійською мовою спочатку перекладається на цю мову, а результат стає записом у словнику за замовчуванням.
- After the default dictionary is updated, each missing country entry in every target language dictionary is translated and saved **immediately per language**.
- Вже перевантажені записи зберігаються без модифікації.
- Якщо переклад не вдається, служба витримає до 3 разів з 30-другими затримками перед переїздом на наступну мову.

### 3 етап — перекладJsonFiles

Послуга порівняння поточного словника локалізації за замовчуванням з знімком, що зберігається з попереднього запуску:

- **Додані ключі** — записи, присутні в поточному за замовчуванням, але не від знімку — переведені в кожну цільову мову, яка вже не має ручного входу для цього ключа.
- **Видалено ключі** — записи, присутні в знімку, але відсутній від поточного за замовчуванням — видаляються з кожного словника мови.
- Переклади завжди мають пріоритет. Якщо цільовий словник вже містить значення для ключа, що запис залишається незалежно від того, що джерело говорить.
- **Такий словник мови зберігається відразу після завершення перекладу**, а не чекаючи всіх мов, щоб закінчити.
- Якщо переклад не виходить на конкретну мову, служба видає автоматично. Тільки постійні помилки (наприклад, непідтримувана мова) викликають, що мова повинна бути пропущена.
- Після запуску поточний словник за замовчуванням зберігається як новий знімок для наступного порівняння.

Всі словники завжди зберігаються з алфавітно сортованими ключами та відступними JSON для читабельності людини.

### Етап 4 — TranslateMarkdownFiles

Послуга проходить налаштовані корені документації (за замовчуванням: ) і обробляє кожен вихідний файл, що рекурсивно:

1. Цей сайт використовує файли cookie та файли cookie. Продовжуючи користуватися нашим сайтом, ви погоджуєтеся з використанням файлів cookie.
2. Файл, поруч із вихідними доріжками за мовними, заблокувати статус перекладу, що дає можливість **incremental re-translation** тільки не вдалося блоків.
3. При збереженні хешу з попереднього пуску (поставте в файл поряд з вихідним файлом, або в тимчасове місце впадання) порівнюється з поточним хешем.
4. Для кожної цільової мови, відповідний файл також перевіряється на структурну цілісність.
5. Будь-який цільовий файл, який відсутній, має застарілий хеш, не вдалося перевірити структуру, або містить неперевершені блоки, призначені для повторного перенесення.
6. **Each target language is translated and saved independently** — if Czech succeeds but French fails, the Czech file is still written to disk.
7. Успішно переведені файли дійсні для структурної пари з джерелом (рівні підрахунки заголовка, список елементів, блоки кодів, блокноти, посилання, сміливі /italic маркери, HTML теги) до їх написання на диск.
8. Якщо всі цільові файли для виходу джерела, новий хеш зберігається поруч з джерелом. Якщо написання наступного джерела не вдається (наприклад, в режимі читання), хеш повертається до тимчасового каталогу.
9. Якщо будь-який цільовий переклад не виконує перевірку, метадані позначають ті блоки як неперекладні, так що вони перераховуються на наступному етапі.

### Етап 5 — СторінРезультати

Зведена збірка і публікація. До складу входить:

- Торговий центр UTC запускає та завершує часові запаси.
- Кількість збережених локальних файлів JSON, збережених файлів Markdown, збережених хеш-файлів і випадкових записів.
- Будь-які помилки зберігання, зібрані під час виконання.
- Статистика перекладу (перекладна кількість, пропущена кількість, кількість помилок).

## Логічна логіка перекладу

Трубопровід реалізує два рівні стійкості:

### Стенд-рівнева птиця (TranslationRetryService)

- Якщо письмовий запит не вдається після внутрішньої речення ЛібреТранслата, виконує до 3 додаткових стадійно-рівневих речення з 30-другими затримками.
- Маскування власників: Назволені власники місця () в тексті тимчасово замінені на безпечні токени () перед перекладом і відновленим після того, як переклад і відновлення граматики в цільових мовах.

### Перевірка мови

- Перед перекладом на цільову мову, служба виправляє мову підтримується сервером перекладів.
- Непідтримувані мови пропускаються з попередженням, запобігаючи повторним спробам.

### Розмітка блочного рівня птиця

- Розмітка перекладів здійснюється блок-by-block (головки, абзаци, пункти списку).
- Якщо індивідуальний блок не передається перекладу, він позначається як неперекладений у файлі метаданих та перерозподіляється на наступний пробіг трубопроводу.
- Послуга відстежує мову, статус заблокування у файлах поряд з кожним вихідним кодом.

## Живий переклад Dashboard

Серверний проект включає в себе сторінку адміністратора, що підключається до вузла SignalR і відображає всі події трубопроводів в режимі реального часу.

- Відображається статус підключення, кількість повідомлень, а також вітальний стіл всіх подій.
- Кольорово-кодовані рядки: синій для початку етапу, зелений для завершення, червоний для помилок.
- Підтримує очищення корму та експорту всіх повідомлень до JSON.
- Автовідключення з відключенням, якщо краплі з'єднання.

## Принципи проектування

- **Modularity**: Each translation concern is isolated in its own service for maintainability and testability.
- **Розвиток нерухомості**: Відносники та файли розмітки зберігаються на мові відразу після перекладу, зменшення тиску пам'яті та надання більш раннього зворотного зв'язку.
- **Resilience**: Multiple retry levels (HTTP, stage, block) ensure transient failures do not block the pipeline.
- **State tracking**: Per-file metadata (`.translation-meta.json`) and hash files enable precise incremental work on subsequent runs.
- **Real-time видимість**: За допомогою SignalR для моніторингу та знеболювання.
- **Manual translations always have priority over automatic additions.**
