# Резюме на промените в службата за автоматичен превод

## Преглед

Настоящият документ обобщава всички промени, направени в услугата за автоматичен превод на Dita, включително архитектурата, новите функции, подобренията на обсерваторията и подобренията на локализацията.

## Промени в архитектурата

### Обоняема услуга за превод

Монолитът е разложен в четири специализирани служби, координирани от лек оркестър:

- **BackendTranslationService** — Pipeline orchestrator (server validation, stage delegation, error handling)
- **CountriesTranslation Service**  год
- **LocalizationTrancationService** JSON речник синхронизация (добавени/премествани ключове)
- **ДокументиТранслузионнаУслуги** .
- **SignalRPublisher** — Real-time progress reporting via SignalR
- **TranslationRetryService** — Stage-level retry with placeholder preservation

### Ползи

- **Разделяне на притесненията **: Всяка услуга обработва един превод домейн
- ** Устойчивост **: По-малките класове са по-лесни за разбиране и изпитване
- ** Разширяване **: Нови цели за превод могат да бъдат добавени чрез прилагане на интерфейс
- ** Надеждност**: Независимите услуги осигуряват по-добра изолация на грешките

## Нови характеристики

### Монитор на живо

**Location**: `/Admin/LiveTranslation`

Нова администраторска страница, която осигурява видимост в реално време в преводаческия тръбопровод:

- Показване на всички събития на SignalR при появата им
- Цветно-кодирани типове съобщения (синьо=стартиран, зелено = завършен, червено = error)
- Банер за състоянието на връзката с автоматично свързване
- Брояч на съобщения и експортиране в JSON

### Име на титулярите

Сега системата за локализация подкрепя имената на акционерите () за подобряване на граматиката на различни езици:

```csharp
// Usage in code
var message = Localizer["WelcomeMessage", new Dictionary<string, string>
{
    ["userName"] = "John",
    ["count"] = "5"
}];
// Result: "Hello John, you have 5 new messages"
```

Характеристики:
- Стойности на държателя, предоставени в работно време или съхранявани в
- Автоматично маскировка / възстановяване по време на превод за предотвратяване на корупцията
- Назад съвместими със съществуващите позиционни притежатели

### Непреки преводи

Маркдаун файловете се превеждат постепенно:

- ** Per-language saving **: Всеки целеви език се записва веднага след превода, намаляване на налягането на паметта
- **Блок ниво проследяване **: песни статус на превод на блок
- ** Селективен опит **: Само неуспешни блокове са препреведени в следващия ход
- ** Метаданни постоянство **: Държавата превод оцелява прилагането рестартира

### Подобрена ритмична логика

Три нива на устойчивост:

1. **HTTR retrie ** (LibreTranslateService): 5 опита с експоненциално отстъпление (1s...)
2. **Stage retry** (TranslationRetryService): 3 additional attempts with 30s delays
3. **Block retrie ** (ДокументиTranslation Service): Неуспешни блокове Markdown retried on next run

### Докладване на сигнала

Доклади в реално време за напредъка при всички тръбопроводни операции:

- Всеки етап публикува събития
- На езика напредък, публикуван като събития
- Събитията с грешки включват подробен контекст (източник, код за грешка, съобщение)
- Поредица номера гарантират поръчване в рамките на всеки пробег

## Миграционен път

Не се изисква миграция. Образуването е вътрешно:

1. Старата е запазена като препратка и след това заменена
2. Регистрациите на DI бяха актуализирани за използване на нови интерфейси
3. Всички съществуващи потребители на невиждани промени

## Подобрения на ефективността

- **Начин на използване на паметта **: Файлове, записани на език, веднага, вместо да държат всичко в паметта
- **Faster intral runs **: Само променени/невалидни блокове Markdown са препреведени
- **Better visibility**: Real-time progress helps diagnose slow stages
