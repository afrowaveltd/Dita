# هيكل الترجمة التحريرية

هذه الوثيقة تصف الهيكل النموذجي لنظام الترجمة التلقائي لـ (ديتا)، الذي بدأ لتحسين القدرة على الصمود والقابلية للاختبار والقدرة على الصمود.

## أهداف التصميم

وتناولت إعادة التصنيع عدة شواغل تتعلق بالتصميم الاحتكاري الأصلي:

- ** تفصيل الشواغل**: وكل مجال من مجالات الترجمة التحريرية (البلدان، والقاموس المشتركون، والميزون) معزول.
- ** الثبات التدريجي**: وتُوفَّر الملفات لكل لغة مباشرة بعد الترجمة التحريرية، مما يقلل من استخدام الذاكرة ويوفر نتائج سابقة.
- ** الصلاحية**: تُعالج مستويات الاسترداد المتعددة حالات الفشل العابر دون إعاقة خط الأنابيب بأكمله.
- ** القابلية للملاحظة**: ويتم الإبلاغ عن كل عملية هامة عن طريق " سينالر " لرصدها في الوقت الحقيقي.
- ** القابلية للتكرار**: ويمكن إضافة أهداف جديدة للترجمة عن طريق تنفيذ واجهة واحدة.

## شطب الخدمة

### الدائرة الخلفية

** المسؤوليات**:
- إدارة دورة الحياة في خط الأنابيب (البداية، الإنجاز، التعامل مع الأخطاء)
- التحكم في التماثل على أساس التماثل (المغامرات المتداخلة)
- التحقق من صحة الموظفين (الارتباط، توافر اللغات، التشكيلة)
- تفويض الخدمات الفرعية

**Does NOT contain**:
- منطق الترجمة
- ملف i/o لصيغ محددة
- المنطق

### خدمات الترجمة التحريرية

** المسؤوليات**:
- اقرأ من الدليل
- تمحيص الأسماء القطرية في القاموس المحلي الافتراضي
- ترجمة أسماء البلدان المفقودة إلى اللغة المستهدفة
- وفّر كل من القاموس المستهدف فور ترجمته

** السلوكيات الرئيسية**:
- إذا كانت اللغة الافتراضية هي الانكليزية: الأسماء القطرية المخزنة حسب الاقتضاء
- إذا كانت لغة التقصير هي لغة أخرى: تترجم الأسماء الإنكليزية إلى لغة غير مقصودة أولا
- كل لغة يتم تجهيزها بصورة مستقلة عن طريق حلقة إعادة النظر الخاصة بها

### خدمات الترجمة التحريرية

** المسؤوليات**:
- تحديد مفاتيح مضافة/مزيلة عن طريق مقارنة القاموس الافتراضي الحالي مع الطلقة السابقة
- ترجمة المفاتيح المضافة إلى كل لغة مستهدفة
- إزالة المفاتيح المحذوفة من كل لغة مستهدفة
- أطلقوا النار من أجل المقارنة القادمة

** السلوكيات الرئيسية**:
- تعطى الترجمات اليدوية دائما الأولوية (لم تبالغ في الكتابة)
- تُترجم المفاتيح المضافة وتُنقذ على الفور
- تُحذف مفاتيح السحب على الفور لكل لغة
- (سنابشوت) لا يتم إنقاذها إلا بعد أن تكتمل جميع اللغات بنجاح

### خدمات الترجمة التحريرية

** المسؤوليات**:
- تم تشكيل الجذور المكوّنة
- الكشف عن الملفات المصدرية المتغيّرة باستخدام هزة sha-256
- حالة الترجمة التحريرية حسب المسار
- قفل مطوّل مع كل قفل
- هيكل قياس القيمة بعد الترجمة التحريرية
- وفر كل ملف من ملفات اللغات المستهدفة بشكل مستقل

** السلوكيات الرئيسية**:
- الرعي على مستوى البلوك: العناوين، الفقرات، البنود المدرجة في القائمة تترجم بصورة منفصلة
- مسارات البيانات الفوقية التي خلفت/غيرت كل لغة
- تُسترجع المباني الفاشلة على المدى التالي دون إعادة ترجمة المباني الناجحة
- ويكفل التحقق من الهيكل عد العناوين، والقوائم، والكتل الرمزية، وما إلى ذلك من مصادر المطابقة

## استراتيجية إعادة التأهيل

وينفذ النظام عمليات إعادة تقييم على ثلاثة مستويات:

### المستوى ١ - برنامج " HTTP " )LibreTranslateService(

- ما يصل إلى 5 محاولات مع التراجع الهائل (1، 2، 3، 4، 5)
- توقيت الشبكة اليدوية، و5x أخطاء، وفشل عابر
- البناء في تشكيلة عملاء فريق الأمم المتحدة المعني بنقل التكنولوجيا

### المستوى ٢ - المرحلة )مراجعة الترجمة التحريرية(

- ما يصل إلى 3 محاولات مع تأخير 30 ثانية
- Re-drives the entire translation request after HTTP-level retries are completed
- تُطبَّق على هذا المستوى قناعة الملاجئ واستردادها

### المستوى ٣ - القفل )دائرة الوثائق(

- كتل قياس فردية تُحدَّد في البيانات الوصفية
- أُعيد تلقائياً على خط الأنابيب التالي
- المباني الناجحة لا تعاد صياغتها

## تدفق البيانات

### ترجمة القاموس

```
[Default Dictionary]
       ↓
[Compare with Snapshot]
       ↓
[Detect Added/Removed Keys]
       ↓
For each target language:
   ├─ Load existing dictionary
   ├─ Apply removals
   ├─ Translate additions (with retry)
   └─ Save dictionary immediately
       ↓
[Save new snapshot]
```

### الترجمة التحريرية

```
[Source File]
       ↓
[Compute Hash]
       ↓
[Compare with stored hash]
       ↓
[Load translation metadata]
       ↓
For each target language:
   ├─ Extract translatable blocks
   ├─ For each block:
   │   ├─ Check metadata (already translated?)
   │   ├─ Translate with retry
   │   └─ Mark success/failure in metadata
   ├─ Reconstruct Markdown
   ├─ Validate structure
   ├─ Save target file
   └─ Save metadata
```

### ترجمة الاسم القطري

```
[countries.json]
       ↓
[Build set of country keys]
       ↓
[Update default dictionary]
       ↓
For each target language:
   ├─ Find missing country entries
   ├─ Translate each missing entry (with retry)
   └─ Save dictionary immediately
```

## ثبات الدولة

### طلقات

- ** JSON**: Stored in a file next to the default dictionary (name varies by storage provider)
- ** العرض**: المزامنة التدريجية للإمكانيات بتتبع ما كان موجودا في الفترة السابقة

### ملفات الحشيش

- ** Markdown**: next to the source file
- **Fallback**: `{tempDir}/{sanitizedPath}.hash.json` if primary location is read-only
- ** العرض**: يُتوقع أن تُغيّر المصادر لتجنب إعادة الترجمة غير الضرورية

### البيانات الوصفية للترجمة

- **Markdown**: `{sourceFile}.translation-meta.json`
- ** أحكام**:
  - محتوى المصدر(ح)
- حالة الكتلة التي تتخلل كل لغم (ضوء الفول)
- آخر مستجدات
- ** العرض**: التمكين من إعادة الترجمة الجزئية إلى المباني الفاشلة فقط

### تخزين الملاجئ

- ** File**:
- ** Contents**: Dictionary of key to placeholder name-value couples
- ** العرض**: يوفر القيم الافتراضية لحاملي الأماكن المسمّين عبر التطبيق

```csharp
public interface ISignalRPublisher

    Task PublishStageAsync<T>(Guid runId, ProcessStage stage, T data, ...);
    Task PublishMessageAsync(Guid runId, LocalizationMessageType type, ProcessStage stage, ...);

```

- أرقام التسلسل فريدة من نوعها عن طريق
- يمكن للزبائن كشف الثغرات أو إعادة التنظيم

```csharp
app.MapHub<LocalizationHub>("/hubs/localization");
```

## نقاط التمديد

### إضافة هدف جديد للترجمة

1. إنشاء واجهة جديدة مع
2. تنفيذ الترابط مع المنطق الخاص بكل مجال
3. السجل في حاوية الاستنشاق
4. الحقن في البناء
5. نداء من بعد المراحل الحالية

### سياسة الاستعادة العرفية

تجاوز معايير البناء:

```csharp
services.AddSingleton<TranslationRetryService>(
    sp => new TranslationRetryService(
        sp.GetRequiredService<ILibreTranslateService>(),
        sp.GetRequiredService<IPlaceholderService>(),
        sp.GetRequiredService<ILogger<TranslationRetryService>>(),
        stageMaxRetries: 5,        // More retries
        stageRetryDelaySeconds: 60  // Longer delays
    ));
```

### متعهد أماكن العمل

التنفيذ من أجل تغيير تركيبة أو تخزين مالكي الأماكن:

```csharp
public class CustomPlaceholderService : IPlaceholderService
{
    // Use {{name}} syntax instead of {name}
    // Store in database instead of JSON file
    // Encrypt sensitive placeholder values
}
```

## استراتيجية الاختبار

### اختبارات الوحدة

ويمكن اختبار كل خدمة فرعية بصورة مستقلة:

- Mock to simulate success/failure
- Mock to verify reporting
- Use temporary directors for file I/O
- التحقق من سلوك الادخار لكل لغة

### اختبارات التكامل

- خط الأنابيب الكامل مع حالة ليبر ترانسل
- التصديق الرسائل الموجهة إلى العملاء المرتبطين
- الوقاية من الاختبارات المتزامنة
- هيكل قياس القيمة بعد الترجمة التحريرية

### اختبارات نهاية

- الترجمة التحريرية عن طريق مكتب المدعي العام أو الجدول الزمني
- التحقق من جميع ملفات اللغات المستهدفة
- ملفات البيانات الفوقية المتحققة تحتوي على حالة سرية صحيحة
- محمية الشركات عبر الترجمات

## اعتبارات الأداء

- ** الذاكرة**: منع الادخار فيما بين اللغات من حيازة جميع القاموس في الذاكرة
- **Disk I/O**: تضيف ملفات البيانات الفوقية الفوقية الصغيرة ولكنها تتيح العمل الإضافي
- **Network**: Sequential processing with throtling prevents overwhelming LibreTranslate
- ** اتحاد الجمهوريات الاشتراكية السوفياتية**: SHA-256، المصادقة على التهوية وإعادة التوثيق، هي سرعة بالنسبة إلى تساهل الترجمة
- **SignalR**: رسائل خفيفة الوزن، لا حاجة لضغط حمولة من أجل التقارير النموذجية

## الهجرة من التصميم الأحادي

الأصلي يحتوي على كل المنطق في صف واحد The migration path:

1. Extract country logical →
2. Extract JSON logical →
3. Extract Markdown logical →
4. الإحالة R publishing →
5. منطق التراجع
6. تبسيط أوسجة الوفد فقط

ولا تزال جميع الوصلات البينية القائمة () دون تغيير. مستهلكو خط الأنابيب لا يرون أي تغيرات.
