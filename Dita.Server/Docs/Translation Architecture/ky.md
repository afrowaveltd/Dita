# Котормо архитектурасы

Бул документте Дитанын автоматтык котормо системасынын модулдук архитектурасы сүрөттөлөт, ал тейлөөнү, текшерүүнү жана туруктуулукту жакшыртуу үчүн киргизилген.

## Дизайн максаттары

Рефакторинг баштапкы монолиттик долбоорго байланыштуу бир нече тынчсызданууларды чечти:

- ** Кызыкчылыктарды бөлүштүрүү**: Ар бир котормо домени (өлкөлөр, JSON сөздүктөрү, Markdown) өзүнчө.
- ** Кошумча туруктуулук**: Файлдар котормодон кийин дароо эле тилге сакталат, эс тутумду колдонууну азайтат жана мурунку натыйжаларды берет.
- ** Туруктуулук**: Бир нече торчо деңгээли бүтүндөй түтүктү тосуп албастан, өтмө бузулууларды чечет.
- ** Байкоо жүргүзүү **: Ар бир маанилүү операция реалдуу убакыт режиминде көзөмөлдөө үчүн SignalR аркылуу билдирилет.
- ** Кеңейтүү**: Бирдиктүү интерфейсти ишке ашыруу менен жаңы котормо максаттарын кошууга болот.

## Кызматтын бузулушу

### BackendTranslationService (орхестратор)

** Жоопкерчиликтер**:
- Түтүктөрдүн жашоо циклинин башкаруусу (баштоо, бүтүрүү, каталарды иштетүү)
- Семафорго негизделген бир эле учурда контролдоо (жүргүзүүлөрдүн бири-бирине дал келбешине жол бербейт)
- Серверди текшерүү (латенттик, тилдин жеткиликтүүлүгү, конфигурация)
- Суб-кызматтарга ыйгарым укуктарды берүү

** төмөнкүлөрдү камтыбайт**:
- Котормо логикасы
- I-O файлы белгилүү бир форматтар үчүн
- Кайра кайтуу логикасы

### Өлкөлөр котормо кызматы

** Жоопкерчиликтер**:
- Каталогдон окуңуз
- Өлкөнүн аталыштарын демейки жергиликтүү сөздүккө синхрондоштуруу
- Жоголгон өлкөлөрдүн аталыштарын максаттуу тилге которуу
- Котормодон кийин ар бир максаттуу сөздүктү дароо сактаңыз

** Негизги жүрүм-турум**:
- Эгерде демейки тил англис тили болсо: өлкөнүн аталыштары сакталат
- Эгерде демейки тил башка болсо: англис тилиндеги ысымдар биринчи демейки тилге которулат
- Ар бир тил өзүнчө кайра иштетүү цикли менен өз алдынча иштетилет

### Локализация котормо кызматы

** Жоопкерчиликтер**:
- Кошумчаланган же алынып салынган ачкычтарды учурдагы демейки сөздүктү мурунку сүрөт менен салыштыруу менен аныктоо
- Кошумча ачкычтарды ар бир максаттуу тилге которуу
- Ар бир максаттуу тилден өчүрүлгөн ачкычтарды алып салуу
- Кийинки салыштыруу үчүн сүрөттү сактаңыз

** Негизги жүрүм-турум**:
- Кол менен которулган котормолор ар дайым артыкчылыкка ээ (эч качан ашыкча жазылган эмес)
- Кошумча ачкычтар которулат жана тилге дароо сакталат
- Алып салынган ачкычтар тилге дароо өчүрүлөт
- Бардык тилдер ийгиликтүү аяктагандан кийин гана сүрөт сакталат

### Документтерди которуу Кызмат

** Жоопкерчиликтер**:
- Маркдаун тамырлары рекурсивдүү
- SHA-256 хэштерин колдонуу менен өзгөртүлгөн булак файлдарын аныктоо
- Блокко котормо статусу
- Блок-блок менен которуу
- Котормодон кийин белгилөө структурасын текшерүү
- Ар бир максаттуу тил файлын өз алдынча сактаңыз

** Негизги жүрүм-турум**:
- Блок деңгээлиндеги майда-чүйдө: аталыштар, абзацтар, тизмедеги пункттар өзүнчө которулат
- Мета-маалыматтардын блоктору тил боюнча ийгиликтүү же ийгиликсиз
- Ийгиликтүү блокторду кайра которуусуз кийинки чуркоодо ийгиликсиз блокторду кайра сыноо жүргүзүлөт
- Структураны текшерүү аталыштардын санын, тизмелерди, код блокторун ж.б. дал келүү булагын камсыз кылат

## Кайра кайтуу стратегиясы

Система үч деңгээлде кайра текшерүүлөрдү ишке ашырат:

### 1-деңгээл: HTTP (LibreTranslateService)

- 5 экспоненциалдык резервдик аракеттер (1s, 2s, 3s, 4s, 5s)
- Тармактын убактысын, 5xx каталарын жана өтмө бузулууларды башкаруу
- HTTP кардарлардын конфигурациясына киргизилген

### 2-деңгээл: этап (TranslationRetryService)

- 30 секунддук кечиктирүү менен 3 аракет
- HTTP деңгээлиндеги кайра иштетүүлөр аяктагандан кийин бүтүндөй котормо өтүнүчүн кайра иштетет
- Бул деңгээлде жайгаштыруучу маскалоо жана калыбына келтирүү колдонулат

### 3-деңгээл: Блок (документтерди которуу кызматы)

- Метамаалыматтар менен белгиленген жеке белгилөө блоктору
- Кийинки түтүктөрдө автоматтык түрдө кайра иштетилет
- Ийгиликтүү блоктор эч качан кайра которулбайт

## Маалыматтардын агымы

### JSON сөздүгүнүн котормосу

```
[Default Dictionary]
       ↓
[Compare with Snapshot]
       ↓
[Detect Added/Removed Keys]
       ↓
For each target language:
   ├─ Load existing dictionary
   ├─ Apply removals
   ├─ Translate additions (with retry)
   └─ Save dictionary immediately
       ↓
[Save new snapshot]
```

### Маркуддун котормосу

```
[Source File]
       ↓
[Compute Hash]
       ↓
[Compare with stored hash]
       ↓
[Load translation metadata]
       ↓
For each target language:
   ├─ Extract translatable blocks
   ├─ For each block:
   │   ├─ Check metadata (already translated?)
   │   ├─ Translate with retry
   │   └─ Mark success/failure in metadata
   ├─ Reconstruct Markdown
   ├─ Validate structure
   ├─ Save target file
   └─ Save metadata
```

### Өлкө аталышынын котормосу

```
[countries.json]
       ↓
[Build set of country keys]
       ↓
[Update default dictionary]
       ↓
For each target language:
   ├─ Find missing country entries
   ├─ Translate each missing entry (with retry)
   └─ Save dictionary immediately
```

## SignalR отчету

### Жарыялоочунун абстракциясы

котормо кызматтарын SignalR өзгөчөлүктөрүнөн ажыратат:

```csharp
public interface ISignalRPublisher
{
    Task PublishStageAsync<T>(Guid runId, ProcessStage stage, T data, ...);

```

- Бир эле чуркоодогу билдирүүлөр монотоникалык тартипте берилет

## Узартуу пункттары

### Жаңы котормо максатын кошуу

1. Жаңы интерфейсти түзүү
2. Доменге мүнөздүү логика менен интерфейсти ишке ашыруу
3. DI контейнериндеги реестр
4. Конструкторго инъекциялоо
5. Учурдагы баскычтардан кийинки чакыруу

### Кадимки кайра иштетүү саясаты

Оверрид конструкторунун параметрлери:

```csharp
services.AddSingleton<TranslationRetryService>(
    sp => new TranslationRetryService(
        sp.GetRequiredService<ILibreTranslateService>(),
        sp.GetRequiredService<IPlaceholderService>(),
        sp.GetRequiredService<ILogger<TranslationRetryService>>(),
        stageMaxRetries: 5,        // More retries
        stageRetryDelaySeconds: 60  // Longer delays
    ));
```

### Кадимки жер ээсинин иштетүүсү

Жергиликтүү ээсинин синтаксисин же сактоосун өзгөртүү:

```csharp
public class CustomPlaceholderService : IPlaceholderService
{
    // Use {{name}} syntax instead of {name}
    // Store in database instead of JSON file
    // Encrypt sensitive placeholder values
}
```

## Сыноо стратегиясы

### Бирдиктүү сыноолор

Ар бир суб-кызмат көз карандысыз текшерилет:

- Ийгиликти же ийгиликсиздикти симуляциялоо үчүн мок
- Билдирүүнү текшерүү
- I файл үчүн убактылуу каталогдорду колдонуңуз О О О
- Тилге үнөмдөө жүрүм-турумун текшериңиз

### Интеграциялык тесттер

- Чыныгы (жергиликтүү) LibreTranslate инстанциясы бар толук түтүк
- SignalR билдирүүлөрү байланышкан кардарларга жеткирилет
- Сыноонун бир эле учурда жүргүзүлүшүнүн алдын алуу (семафор)
- Котормодон кийин белгилөө структурасын текшерүү

### Акырындан аягына чейин сыноолор

- API же пландаштыруучу аркылуу которуу
- Бардык максаттуу тил файлдары түзүлгөнүн же жаңыртылганын текшериңиз
- Мета-маалыматтардын файлдары туура блок абалын камтыйт
- Тастыкталган орун ээлери котормолордо сакталат

## Иштин натыйжалуулугун эске алуу

- ** Эстутум **: Тилге үнөмдөө бардык сөздүктөрдү эс тутумунда кармоого тоскоолдук кылат
- ** Диск I/O**: Метамаалымат файлдары кичинекей чыгымдарды кошушат, бирок кошумча иштөөгө мүмкүндүк берет
- ** Тармактык байланыш**: Бир нече жолу иштетүү LibreTranslate ашыкча болушуна жол бербейт
- **CPU**: SHA-256 hashing and regex validation are fast relative to translation latency
- **SignalR**: Lightweight messages, no payload compression needed for typical reports

## Монолиттик дизайндан миграция

Түп нускада бардык логика бир класста камтылган. Миграциялык жол:

1. Өлкө логикасын алып салуу →
2. JSON логикасын алып салуу →
3. Экстракт белгилөө логикасы →
4. Extract SignalR басмаканасы →
5. Экстракттын артка кайтуу логикасы →
6. Оркестрди делегацияга гана жөнөкөйлөтүү

Бардык учурдагы интерфейстер өзгөрүүсүз калат. Бул түтүктүн керектөөчүлөрү эч кандай өзгөрүүлөрдү көрүшпөйт.
