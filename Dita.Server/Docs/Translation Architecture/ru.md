# Переводческая архитектура

Этот документ описывает модульную архитектуру системы автоматического перевода Dita, введенную для улучшения ремонтопригодности, проверяемости и устойчивости.

## Цели дизайна

Рефакторинг решил несколько проблем с оригинальным монолитным дизайном:

- ** Разделение проблем**: Каждый домен перевода (страны, словари JSON, Markdown) изолирован.
- ** Повышенная настойчивость**: Файлы сохраняются на одном языке сразу после перевода, уменьшая использование памяти и предоставляя более ранние результаты.
- **Resilience**: Multiple retry levels handle transient failures without blocking the entire pipeline.
- ** Наблюдение**: Каждая важная операция сообщается через SignalR для мониторинга в режиме реального времени.
- ** Расширяемость**: Новые цели перевода могут быть добавлены путем реализации одного интерфейса.

## Сервисное разложение

### BackendTranslationService (оркестр)

** Ответственность**:
- Управление жизненным циклом трубопровода (начало, завершение, обработка ошибок)
- Конкурентный контроль на основе семафора (предотвращает перекрытие прогонов)
- Проверка сервера (латентность, доступность языка, конфигурация)
- Делегация в субслужбах

** Не содержит **:
- Логика перевода
- Файл I/O для определенных форматов
- Логика повторения

### Страны Услуги по переводу

** Ответственность**:
- Читать из каталога
- Синхронизируйте названия стран в словарь по умолчанию
- Переводим имена пропавших стран на целевой язык
- Сохраните каждый целевой словарь сразу после перевода

**Ключевое поведение**:
- Если язык по умолчанию английский: имена стран, сохраненные как есть
- Если язык по умолчанию другой: английские имена, переведенные на язык по умолчанию
- Каждый язык обрабатывается независимо с помощью собственной петли повторения

### Локализация Услуга перевода

** Ответственность**:
- Обнаружение добавленных / удаленных ключей путем сравнения текущего словаря по умолчанию с предыдущим снимком
- Перевод добавленных ключей на каждый целевой язык
- Удаление удаленных ключей с каждого целевого языка
- Сохранить снимок для следующего сравнения

**Ключевое поведение**:
- Ручные переводы всегда имеют приоритет (никогда не перезаписываются)
- Добавленные ключи немедленно переводятся и сохраняются на одном языке
- Удаленные ключи немедленно удаляются на языке
- Снимок сохраняется только после успешного завершения всех языков

### Услуги по переводу документов

** Ответственность**:
- Прогулка с настроенными корнями Markdown рекурсивно
- Обнаружение измененных исходных файлов с помощью хешей SHA-256
- Статус перевода на каждый блок в
- Перевести блок за блоком с повторным блоком
- Проверка структуры Markdown после перевода
- Сохраните каждый файл целевого языка независимо

**Ключевое поведение**:
- Гранулярность на уровне блоков: заголовки, абзацы, пункты списка переводятся отдельно
- Метаданные отслеживают, какие блоки удались/не удались на языке
- Неудачные блоки перепроверяются на следующем этапе без повторного перевода успешных блоков
- Проверка структуры обеспечивает подсчет заголовков, списков, блоков кода и т. Д. Источник соответствия

## Стратегия повторного использования

Система реализует повторы на трех уровнях:

### Уровень 1 — HTTP (LibreTranslateService)

- До 5 попыток с экспоненциальным выпадением (1s, 2s, 3s, 4s, 5s)
- Обрабатывает тайм-ауты сети, ошибки 5xx и временные сбои
- Встроен в конфигурацию HTTP-клиента

### Уровень 2 — Стадия (TranslationRetryService)

- До 3 попыток с 30-секундной задержкой
- Перенаправляет весь запрос на перевод после того, как запросы HTTP-уровня исчерпаны
- На этом уровне применяется маскировка и реставрация

### Уровень 3 - Блок (Служба перевода документов)

- Отдельные блоки Markdown, которые выходят из строя, отмечены в метаданных
- Автоматически восстанавливается на следующем трубопроводе
- Успешные блоки никогда не переводятся

## Поток данных

### Перевод словаря JSON

```
[Default Dictionary]
       ↓
[Compare with Snapshot]
       ↓
[Detect Added/Removed Keys]
       ↓
For each target language:
   ├─ Load existing dictionary
   ├─ Apply removals
   ├─ Translate additions (with retry)
   └─ Save dictionary immediately
       ↓
[Save new snapshot]
```

### Маркдаунский перевод

```
[Source File]
       ↓
[Compute Hash]
       ↓
[Compare with stored hash]
       ↓
[Load translation metadata]
       ↓
For each target language:
   ├─ Extract translatable blocks
   ├─ For each block:
   │   ├─ Check metadata (already translated?)
   │   ├─ Translate with retry
   │   └─ Mark success/failure in metadata
   ├─ Reconstruct Markdown
   ├─ Validate structure
   ├─ Save target file
   └─ Save metadata
```

### Перевод названия страны

```
[countries.json]
       ↓
[Build set of country keys]
       ↓
[Update default dictionary]
       ↓
For each target language:
   ├─ Find missing country entries
   ├─ Translate each missing entry (with retry)
   └─ Save dictionary immediately
```

## Постоянство государства

### Снимки

- **JSON**: Хранится в файле рядом со словарем по умолчанию (имя зависит от поставщика услуг хранения)
- **Цель**: Возможность инкрементной синхронизации путем отслеживания того, что присутствовало в предыдущем запуске

### Хеш файлы

- **Markdown**: рядом с исходным файлом
- **Обратная связь**: если основное местоположение только для чтения
- **Purpose**: Detects source changes to avoid unnecessary re-translation

### Метаданные перевода

- **Маркдаун**:
- **Содержимое**:
  - Источник контента hh
- Per-language block status (массив булев)
- Последнее обновление Timesamp
- ** Цель**: Возможность частичного повторного перевода только неисправных блоков

### Место хранения

- **Файл**:
- **Содержимое**: словарь ключей к парам имён-значений заполнителей
- **Цель **: Обеспечивает значения по умолчанию для названных заполнителей в приложении

## Сигнал R Отчетность

### Абстракция издателя

отделение переводческих услуг от спецификаций SignalR:

```csharp
public interface ISignalRPublisher
{
    Task PublishStageAsync<T>(Guid runId, ProcessStage stage, T data, ...);
    Task PublishMessageAsync(Guid runId, LocalizationMessageType type, ProcessStage stage, ...);
}
```

### Гарантии последовательности

- Сообщения в пределах одного прогона монотонно секвенированы
- Номера последовательностей уникальны для каждого
- Клиенты могут обнаружить пробелы или переупорядочение

### Картографирование

```csharp
app.MapHub<LocalizationHub>("/hubs/localization");
```

## Точки расширения

### Добавление новой цели перевода

1. Создать новый интерфейс с
2. Внедрение интерфейса с доменной логикой
3. Регистрация в контейнере DI
4. Впрыск в конструктор
5. Звонок после существующих этапов

### Пользовательская политика повторного использования

Параметры переопределения конструктора:

```csharp
services.AddSingleton<TranslationRetryService>(
    sp => new TranslationRetryService(
        sp.GetRequiredService<ILibreTranslateService>(),
        sp.GetRequiredService<IPlaceholderService>(),
        sp.GetRequiredService<ILogger<TranslationRetryService>>(),
        stageMaxRetries: 5,        // More retries
        stageRetryDelaySeconds: 60  // Longer delays
    ));
```

### Обработка на заказ

Внедрение для изменения синтаксиса или хранилища заполнителя:

```csharp
public class CustomPlaceholderService : IPlaceholderService
{
    // Use {{name}} syntax instead of {name}
    // Store in database instead of JSON file
    // Encrypt sensitive placeholder values
}
```

## Стратегия тестирования

### Единичные испытания

Каждая услуга может быть проверена независимо:

- Мокс для имитации успеха/неудачи
- Mock для проверки отчетности
- Используйте временные каталоги для ввода/вывода файлов
- Проверка поведения по сохранению языка

### Интеграционные тесты

- Полный трубопровод с реальным (местным) экземпляром LibreTranslate
- Проверьте сигнал R сообщения доставляются подключенным клиентам
- Профилактика одновременных пробежек (семафор)
- Проверка структуры Markdown после перевода

### Сквозные испытания

- Перевод триггеров через API или планировщик
- Убедитесь, что все файлы целевого языка созданы/обновлены
- Файлы метаданных содержат правильный статус блока
- Подтвержденные заполнители сохраняются во всех переводах

## Соображения в связи с исполнением

- ** Память**: сохранение одного языка не позволяет хранить все словари в памяти
- ** Диск I/O**: Файлы метаданных добавляют небольшие накладные расходы, но обеспечивают дополнительную работу
- **Сеть**: Последовательная обработка с дросселированием предотвращает перегрузку LibreTranslate
- **CPU**: хеширование и валидация SHA-256 являются быстрыми относительно задержки перевода
- **SignalR**: Легкие сообщения, не требуется сжатие полезной нагрузки для типичных отчетов

## Миграция от монолитного дизайна

Оригинал содержал всю логику в одном классе. Путь миграции:

1. Извлеките страновую логику
2. Извлечение логики JSON
3. Извлеките логику Markdown
4. Экстрактный сигнал R Публикация
5. Логика Retry Logic
6. Упростить оркестровку только для делегаций

Все существующие интерфейсы остаются неизменными. Потребители трубопровода не видят никаких изменений.
